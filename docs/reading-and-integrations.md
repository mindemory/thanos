# Reading and integrations

Short notes on why Thanos's pages read the way they do, and on which of a lab's other tools to connect next. Checked in November 2026, against each project's own pages where it could be. Anything that couldn't be checked that way says so.

## How a lab uses it

Most visits are a lookup in the middle of something else. Someone has a purchase form half filled in, or a terminal open, or a scanner booking page, and needs one thing: the chart string, the path to the raw data, which grant, who holds the card. They want it in seconds and then they leave.

People scan pages like this, they don't read them:

- In Nielsen's early tests, 79% of people scanned a new page and 16% read it word by word. The advice was keywords that stand out, plain headings, lists, one idea per paragraph, and the conclusion first ([NN/g, How users read on the web](https://www.nngroup.com/articles/how-users-read-on-the-web/)).
- Eye-tracking finds several scanning patterns, the F-shape among them, and a "layer cake" that reads only the headings. Headings should start with the words that carry the meaning ([NN/g, F-shaped pattern](https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/)).
- The inverted pyramid puts the most important thing first, so a reader gets the point however little they read ([NN/g, Inverted pyramid](https://www.nngroup.com/articles/inverted-pyramid/)).
- Lab handbooks and manuals save time and give everyone new the same start ([eLife, Why every lab needs a handbook](https://elifesciences.org/articles/88853); [Nature, The key to a happy lab life is in the manual](https://www.nature.com/articles/d41586-018-06167-w)). Thanos is that handbook written as questions and answers, so it gets written a question at a time (see also [NN/g, FAQs still deliver great value](https://www.nngroup.com/articles/faqs-deliver-value/)). No study we found measures how much a lab forgets when people leave.

## What makes reference quick to scan

| What the guides say | Where | What Thanos does |
| --- | --- | --- |
| People look things up in reference while they work. It should be plain and factual, with the same shape every time, so things are where people expect them. | [Diátaxis: reference](https://diataxis.fr/reference/), [how-to guides](https://diataxis.fr/how-to-guides/) | Every card has the same shape: the question, then the answer straight under it, then whether it's still right, then who wrote it. The form asks for the answer first and the details after it. |
| Put a copy button on code blocks. Give a block a title or language. | [Material for MkDocs](https://squidfunk.github.io/mkdocs-material/reference/code-blocks/) (`content.code.copy`), [Docusaurus](https://docusaurus.io/docs/markdown-features/code-blocks) (built into the theme, [source](https://github.com/facebook/docusaurus/blob/main/packages/docusaurus-theme-classic/src/theme/CodeBlock/Buttons/index.tsx)), [GitBook](https://gitbook.com/docs/create-content/blocks/code-block) | Code blocks have a copy button and show their language (```` ```bash ````). So do inline values: anything in backticks, plus chart strings, paths and shared-drive addresses written without them ([src/lib/values.ts](../src/lib/values.ts)). The buttons are always visible, not only on hover, so they work on a phone and from the keyboard. |
| Set code, paths and IDs in monospace. | All three | Values are in Geist Mono at normal word spacing, without ligatures, so what you see is what you copy. A short value stays on one line, so a chart string never breaks at a hyphen. Repository names on the Code page are mono too, each with a copy button for cloning. |
| Use tables for facts that line up. Use tabular figures so the numbers line up too. | [MDN: font-variant-numeric](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-variant-numeric) | Answers can have tables, with tabular figures and right-aligned number columns (`---:`). Dates and counts in lists use tabular figures. Numbers elsewhere were already in Geist Mono. |
| Keep lines comfortable to read: 45 to 90 characters, or 50 to 75. | [Practical Typography](https://practicaltypography.com/line-length.html), [Baymard](https://baymard.com/research-articles/line-length-readability) | Prose in answers and the sentence under a page's heading stop at 34em, about 75 characters. Code and tables can use the full width. The measure is in `em`, not `ch`: Geist's 0 is wide, so 62ch came out at about 91 characters. |
| Use callouts (note, warning) to set things apart. | [Material](https://squidfunk.github.io/mkdocs-material/reference/admonitions/), [Docusaurus](https://docusaurus.io/docs/markdown-features/admonitions), [GitBook](https://gitbook.com/docs/create-content/blocks/hint) | Thanos has one of its own, the "may be out of date" warning under an answer. Callouts inside answers are left for later. |
| Text needs 4.5:1 contrast, and a control's edge 3:1. Focus must show, and nothing on screen may hide it. | WCAG 2.2: [1.4.3](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), [2.4.7](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html), [2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html), [2.4.13](https://www.w3.org/WAI/WCAG22/Understanding/focus-appearance.html) | Tertiary text was 4.4:1 on a row under the pointer and is now 4.6:1 or more, in both themes. Text fields had a 1.5:1 edge and now have 3.2:1 (dark) and 3.4:1 (light). Fields get the same 2px focus ring as everything else, where before they only had a tinted border. A row that is one big link shows the ring round the whole row. On a phone, focus scrolls clear of the top bar and the tab bar. A skip link jumps past the rail, and search says aloud how many matches it found. |

## Accessibility lint

[eslint-plugin-jsx-a11y](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y) is MIT-licensed. `eslint-config-next` already installs and registers it, but turns on only six of its rules, as warnings. Thanos now runs the plugin's whole recommended set (34 rules), as errors, using the copy Next registers ([eslint.config.mjs](../eslint.config.mjs)). Installing a second copy would clash with Next's under the same name, and the plugin's peer range stops at ESLint 9 while Thanos uses ESLint 10.

It found two things, both `autoFocus` (on sign-in, and on the ask form), and both are gone. A check by hand found one more that lint can't see: the switch between asking and sharing claimed to be tabs, with no panels or arrow keys. It is now two buttons, one of them pressed.

## Integrations

Thanos already reads a lab's Slack (from an export, public channels only, drafted by a model on the lab's own computer) and its GitHub (public repositories, or private ones with a token). The others, in the order worth doing:

| Tool | Getting content out | Sign-in | Terms and licence | Watch for |
| --- | --- | --- | --- | --- |
| **Google Docs** | No API needed: File › Download › Markdown, since [July 2024](https://workspaceupdates.googleblog.com/2024/07/import-and-export-markdown-in-google-docs.html). Through the API, Drive [`files.export`](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/export) gives `text/markdown` ([formats](https://developers.google.com/workspace/drive/api/guides/ref-export-formats)). | OAuth 2.0. The `drive.file` scope (only the files someone picks) is non-sensitive and the one Google recommends ([scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)). | [Google APIs Terms of Service](https://developers.google.com/terms), and the [API Services User Data Policy](https://developers.google.com/terms/api-services-user-data-policy) (not read in full). | `drive.readonly` is a restricted scope: it needs verification, and a yearly security assessment if the data passes through a server. An Internal app inside the university's own Workspace is exempt ([restricted scopes](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification)). An export is capped at 10 MB. |
| **Notion** | No API needed: export a page or workspace as Markdown & CSV ([export](https://www.notion.com/help/export-your-content)). The API returns a page as Markdown with [`GET /v1/pages/{id}/markdown`](https://developers.notion.com/reference/retrieve-page-markdown). | An internal connection token, a personal access token, or OAuth for a public connection ([authorization](https://developers.notion.com/guides/get-started/authorization)). | Notion's Developer Terms ([linked here](https://www.notion.com/help/template-gallery-guidelines-and-terms); the page builds itself in the browser, so its text wasn't checked). | 180 requests a minute per connection ([limits](https://developers.notion.com/reference/request-limits)). Pages over about 20,000 blocks are cut short. Notion also runs an official [MCP server](https://developers.notion.com/guides/mcp/overview). |
| **protocols.io** | API v4 returns a protocol and its steps as JSON ([API](https://apidoc.protocols.io/)). | A client token for public content, or OAuth. | People keep their content and license it CC BY ([terms](https://www.protocols.io/terms)). Public protocols show CC BY 4.0, though some authors pick other licences. | 100 requests a minute. A card that copies a protocol has to keep its licence and its authors. Linking is simpler: show the title and version of a protocols.io link or DOI in an answer. There is an official MCP server too. |
| **Zotero group libraries** | Web API v3, `/groups/<id>/items`, as JSON, BibTeX or CSL JSON ([basics](https://www.zotero.org/support/dev/web_api/v3/basics)). The desktop app serves the same API locally. | None for a public group. An API key or OAuth 1.0a for a private one. | [Terms of service](https://www.zotero.org/support/terms/terms_of_service), with no API-specific clause. Zotero's own code is AGPL-3.0, which doesn't reach apps that call the API. | No published rate limit; the API sends `Backoff` or 429 when it wants a pause. Useful for one card ("what should I read first?"), not for answers. |
| **Benchling** | Notebook entries through API v3 ([entries](https://docs.benchling.com/docs/working-with-entries)). The document APIs are in beta. | App credentials, OAuth, or a personal API key; keys made after 7 August 2026 expire in 30 days ([auth](https://docs.benchling.com/docs/authentication)). | Free for academics ([academic](https://www.benchling.com/academic)), under [terms](https://www.benchling.com/terms-of-service) that forbid bots and scrapers. Paid tenants fall under a services agreement. | Whether academic accounts get the API couldn't be checked: Benchling's help centre turns away automated reads. Link to entries; don't import them. |
| **LabArchives** | API documentation is behind a login. A site admin asks LabArchives for a key ([platform updates](https://www.labarchives.com/blog/labarchives-platform-updates)). | Unverified: an access key and password that sign each call, with OAuth for newer integrations. | [Terms of use](https://www.labarchives.com/terms-of-use/), which depend on when the lab bought it. The PDFs weren't checked for API clauses. | An enterprise contract the lab may not control. Link to notebook pages; don't import them. |

What to do next:

1. **A folder of Markdown.** Most labs' written-down knowledge is in Google Docs or Notion, and both export Markdown without an API, an app review or a token. An importer like `import-slack` could read a folder of exported files and turn each heading and the text under it into a draft for the Review page. It would follow the same rules: on the lab's own computer, a model in Ollama, and nothing reaches the lab until an admin keeps it. One importer covers both tools, and more besides (an Obsidian vault, a GitHub wiki).
2. **protocols.io links.** When an answer links a protocol, show its title, version and licence from the public API, so a reader can tell it's the right one without opening it. Nothing is copied, so the licence question doesn't come up.
3. **Google Drive, live.** Only if exporting files gets tiresome: a picker using `drive.file`, which needs no verification and sees only the files someone picks.
4. **Zotero.** One card that lists a public group library, if a lab asks for it.
5. **Benchling and LabArchives.** Links only. Their APIs depend on the university's contract, and their notebooks hold more than a lab's everyday answers.

## Left for later

- Search as a proper combobox (`aria-activedescendant`), so a screen reader hears the result the arrow keys land on. For now it hears how many matched.
- Callouts inside answers (a note, a warning), and links to the headings of a long answer.
- A "copy link" button on a card, for pasting into the lab's Slack.
